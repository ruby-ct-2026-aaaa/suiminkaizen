# 峰小輔の7日間 — プログラム設計書 v0.2.1 / LIVE edition

対象：Ruby + Gosu / 協働制作向けの試作版

## 1. 確定要件

「睡眠ゲージ」「睡眠気絶ゲージ」は同じ値として扱い、画面では**睡眠・気絶ゲージ**と表示する。

| 項目 | 仕様 |
|---|---|
| 主人公 | 架空のショートスリーパー「峰小輔」 |
| 表現 | ドット絵。斜め見下ろしの疑似3D |
| 行動 | 筋トレ・お風呂・サプリメント・整体・カメラ救出のミニゲーム |
| ゲージ下限 | 0。ゲーム内での通常・健康な状態 |
| ゲージ上限 | 1000。到達した時点で強制睡眠、ゲームオーバー |
| 回復 | 成功したミニゲームの難易度・成功度によって変化 |
| 仮眠 | 1日を乗り切ると30分だけ可能。ゲージ−30、下限0 |
| 勝利 | 7日間、一度も強制睡眠しない |
| 実装環境 | Ruby + Gosu |

ゲーム内の健康表現・仮眠・サプリメントは架空の設定で、現実の効能や数値には対応しない。

## 2. 試作で追加した仮設定

以下はプレイできるように決めた調整値であり、メンバーの意見で変更してよい。

| 項目 | 仮設定 | 変更場所 |
|---|---|---|
| 初期ゲージ | 0 | `GameState#initialize` |
| 1日の起床時間 | ゲーム内00:00〜23:30を実時間90秒へ圧縮 | `DAY_SECONDS` / `AWAKE_MINUTES` |
| 残り30分 | 仮眠またはスキップで24:00へ進む。待ち時間の演出は省略 | `complete_day` |
| 1週間の長さ | 起床時間の合計10分30秒＋メニュー操作時間 | `DAYS` / `DAY_SECONDS` |
| ミニゲーム制限 | 最大8秒。お風呂以外は必要回数を終えると早期終了 | `MINI_SECONDS` |
| 同じ設備の待ち | 終了後、実プレイ時間12秒。翌日にはリセット | `COOLDOWN_SECONDS` |
| 失敗 | 回復0。追加ペナルティはないが、その間の時間増加は残る | `reward_for` |
| 仮眠の選択 | 行う・スキップを選択できる | `complete_day(nap:)` |
| ゲージ持ち越し | 翌日にリセットしない | `complete_day` |
| 説明・結果画面 | 時間を停止 | `running?` |

1日終わりの23:30を「起きている区間のクリア」と判定する。そこで最後の30分を処理して、24時間＝1日が完了する。
7日目も同じ処理を通った後に勝利画面を表示する。
仮眠回復を受けられるのは各日1回だけで、日中に任意で寝ることはできない。

## 3. ゲージ計算と判定順

### 時間経過

| 日 | 1日の自然増加 | 1秒あたりの増加（概算） |
|---|---:|---:|
| 1 | +975 | +10.83 |
| 2 | +1050 | +11.67 |
| 3 | +1125 | +12.50 |
| 4 | +1200 | +13.33 |
| 5 | +1275 | +14.17 |
| 6 | +1350 | +15.00 |
| 7 | +1425 | +15.83 |

前版の自然増加を1.5倍にした。1日の長さ・ゲージ上限・回復量は従来どおり。

```text
1秒あたりの増加 = DAILY_GAIN[日数 - 1] / DAY_SECONDS
新しいゲージ = min(1000, 現在のゲージ + 1秒あたりの増加 × 経過秒)
```

毎フレーム一定値を足さず、経過秒数 `dt` を使う。部屋とミニゲームは同じ時計を使う。
処理が大きく遅れた場合、画面側は1回の更新を最大0.1秒に制限する。長い停止から一気に気絶するのを避けるための試作用の扱い。

### 優先順位

1. その入力・更新時点まで時間を進める。
2. 1000到達を最優先で判定。到達なら即座に強制睡眠。
3. 生存中のみミニゲームの成功を確定し、回復を適用する。
4. 1日終了時に日別結果と仮眠の選択へ進む。
5. 7日分を終えると勝利。

1000到達と日付変更が同時なら敗北。気絶後の成功報酬による復帰は認めない。
残り8秒以下では新規ミニゲームを開始しない。ミニゲーム更新も残り制限時間までに区切り、報酬確定をフレームの遅延で日付の後へずらさない。
内部は小数で持ち、ゲージ本体は整数切り捨てで画面表示する。結果の実減少量は小数1桁まで表示する。

## 4. ミニゲームと回復量

| ゲーム | ルール | 成功度 q の計算 | 難化させる項目 |
|---|---|---|---|
| 筋トレ：リズム・リフト | 動くバーを中央に合わせて5回押す | 各回の中心への近さを0〜1にし、5回分の平均。未入力は0点 | バー速度・中央ゾーン幅 |
| お風呂：バブル・バランス | 左右操作で泡を光るゾーンに保つ | ゾーン内にいた時間 ÷ 8秒 | 泡の流れ・ゾーン幅・ゾーンの移動 |
| サプリメント：星粒メモリー | 光った星粒の順番を覚えて入力する | 正しい位置の入力数 ÷ 出題数 | 出題数3/4/5・表示速度 |
| 整体：まぶた防衛 | 矢印と同じ方向へ素早く入力 | 正答時は1−0.5×反応時間/制限、誤答・時間切れ0。全問平均 | 出題数5/6/7・制限0.95/0.80/0.65秒 |
| 配信カメラ救出 | 6台から光ったカメラを番号かクリックで選ぶ | 整体と同じ採点 | 出題数4/5/6・制限1.15/0.92/0.70秒 |

お風呂の温度やサプリの量は使わない。記憶ゲームの星粒は架空のアイテム。
記憶ゲームでは見本が表示されている間の入力を無効にし、制限時間切れの未回答は0点とする。
筋トレの同時連打には0.35秒の間隔を設ける。
新しい2種は出題時刻が固定で、連打しても次の問題が早く出ない。合図前の入力は無効。
最初の合図は0.45秒。整体の出題間隔は1.35/1.05/0.88秒、カメラは1.60/1.30/1.10秒。
整体の閉眼ポーズはミスを表す演出で、強制睡眠の判定はゲージ1000への到達だけで行う。

| 選択難易度 | 成功ライン t | 成功時の最小回復 | 最大回復 |
|---|---:|---:|---:|
| やさしい | 55% | −80 | −120 |
| ふつう | 65% | −140 | −200 |
| むずかしい | 75% | −210 | −300 |

```text
q < t の場合：回復量 R = 0
q >= t の場合：R = 四捨五入(最小回復 + (最大回復 − 最小回復) × (q − t) / (1 − t))
実際の減少 = min(現在のゲージ, R)
回復後のゲージ = max(0, 現在のゲージ − R)
```

例：ふつうで成功度80%なら、`140 + 60 × (0.80−0.65)/(1−0.65)` を四捨五入して**−166**。
ゲージが100なら、獲得効果−166に対して実際の減少は−100となる。
成功ライン未満はMISS、成功時は92%以上=S、80%以上=A、それ未満=B。

## 5. プログラムの役割分担

| ファイル / クラス | 担当 |
|---|---|
| `main.rb` | Gosu起動、読み込み失敗時の案内 |
| `config/balance.rb` / `Balance` | 日数・ゲージ・回復・ミニゲーム説明の設定 |
| `lib/game_state.rb` / `GameState` | 時間・ゲージ・日数・状態・勝敗・仮眠・報酬 |
| `lib/game_window.rb` / `GameWindow` | Gosuイベント、キーボード・マウス、UI、各画面 |
| `lib/stream_window.rb` / `StreamWindow` | 実際の起動先。従来の画面を継承し、配信画面・新入力・演出を追加 |
| `lib/stream_feed.rb` / `StreamFeed` | 動作別のコメント、流れる位置、表示待ち、チャット履歴 |
| `lib/hallucinations.rb` / `Hallucinations` | 出現段階・退散・再出現タイマー。Gosu非依存 |
| `lib/animation.rb` | 操作結果からコマを選択し、スプライトを描画・切り出し |
| `lib/world.rb` / `World` | 疑似3D、移動、家具の当たり判定、経路探索、仮ドットの描画 |
| `lib/minigames/base.rb` / `Minigames::Base` | 時間・終了・入力・成功度の共通形式 |
| `training.rb` / `Training` | 筋トレの採点と入力処理 |
| `bath.rb` / `Bath` | 泡の移動と滞在時間の採点 |
| `supplement.rb` / `Supplement` | 出題・記憶・入力順の採点 |
| `reaction.rb` / `Reaction` | 固定時刻で出題する反応ゲームの共通処理 |
| `massage.rb` / `Massage` | 左右の合図とまぶた防衛 |
| `camera.rb` / `Camera` | 6台のカメラ救出 |
| `lib/minigames.rb` / `REGISTRY` | ミニゲームIDと実装クラスの対応 |
| `assets/` | 原画像、20コマの人物スプライト、4コマのクイヤ、日本語フォント、ライセンス |
| `test/` | 進行・採点・移動と、実Gosuの入力・描画の検証 |

**重要：各ミニゲームからゲージや日数を直接変更しない。**
ミニゲームは「終了したか」「成功度0〜1」を返し、`GameState` が回復と勝敗を一元管理する。
新しい行動のルールを追加しても、1000判定や仮眠処理を書き直す必要がない。

共通インターフェース：

```ruby
mini = Minigames::REGISTRY.fetch(activity_id).new(difficulty)
mini.input(:action)                       # 1回の押下
mini.update(dt, left: false, right: true) # 時間と長押し
state.finish_minigame(mini.quality) if mini.done?
```

## 6. 状態と画面の流れ

| 状態 | 内容 | 時計 | 次へ進む条件 |
|---|---|---|---|
| `title` | タイトル | 停止 | スタート→room |
| `room` | 部屋を移動 | 進む | 設備→choose / 日終了→day_clear / 1000→game_over |
| `choose` | 説明・難易度 | 停止 | 難易度決定→mini / 戻る→room |
| `mini` | ミニゲーム | 進む | 成功・失敗→result / 1000→game_over |
| `result` | 成績と回復量 | 停止 | 決定→room |
| `day_clear` | 30分仮眠の選択 | 停止 | 翌日room / 7日目終了ならvictory |
| `paused` | 一時停止 | 停止 | 操作で直前のroom/miniへ戻る |
| `game_over` | 強制睡眠 | 停止 | 最初から |
| `victory` | 1週間の結果 | 停止 | 最初から |

OS上で別のウィンドウに切り替えると `lose_focus` で自動停止する。戻しただけでは再開せず、EscまたはEnterで再開する。

## 7. 疑似3Dの実装

本格的な3Dエンジンは使わず、2D描画で高さと前後関係を表す。

```text
画面X = 184 + (マップX − マップY) × 18
画面Y = 57  + (マップX + マップY) × 9 − 高さ
```

- 床は10×9マスの菱形。家具は上面・側面を別の四角形で描く。
- キャラと家具の描画順を奥行きに合わせて並べ、前後の重なりを出す。
- 380×235の低解像度で描いた部屋を `retro: true` で2倍表示し、ドットをぼかさない。
- 移動・当たり判定はマップ座標で計算する。クリック位置は逆変換する。
- 自動移動は4方向の幅優先探索で家具を避ける。
- 現在の歩行キャラはコードで描いた仮素材。今後、専用の歩行スプライトへ交換できる。
- 原画像はプレイヤー視点の人物欄に表示。タイトルと配信画面は描き起こしの人物スプライトを使う。

`Gosu.render` の描画先を入れ子にしない。スクリーンショットでは部屋の描画を先に完成させてから画面全体を保存する。

## 8. 追加アイデアの取り込み方

チームのメンバーは、次の6点をセットで提案すると実装へ移しやすい。

1. 名前・行動の説明
2. プレイヤーが何を押すか
3. 終了・成功・失敗の条件
4. 成功度を0〜1にする計算
5. 難易度を上げる要素
6. 部屋で使う場所と見た目

実装時は、まず `Minigames::Base` を継承したクラスを追加し、`REGISTRY` に登録する。
続いて `Balance::ACTIVITIES` に名前・説明・色、`World::STATIONS` に設備の位置を追加する。
描画は `StreamWindow#draw_minigame` と個別の描画メソッドへ追加する。
現在は5枚の設備カードと1〜5キーを使う。6種類目以降はカード配置とキーを拡張する。
配信コメントは `StreamFeed::LINES`、アニメーションは `Animation` とアトラスの行に追加する。
ゲージ上限・日付・仮眠・勝敗の変更が必要な案だけは、`GameState` 側も見直す。

## 9. 試作の確認と次の判断

- ゲージの上下限、1000判定、同時イベント、仮眠の重複禁止、翌日持ち越しを確認する。
- ミニゲームの成功・失敗、入力前の無効化、時間切れ、放置攻略の有無を確認する。
- ふつうの最高点を1日7回取得する進行モデルで、7日間クリアできることを確認する。
- 実際の移動・出題・採点を通す自動プレイヤーでも全5種類を巡回して7日間を完走する。
- 27項目・1780 assertionsの自動テストを `ruby test/test_game.rb` で実行できる。
- Gosuの入力経路と描画は `ruby test/smoke_gosu.rb`、画面確認は `ruby tools/capture.rb` を使う。

実行結果：Ruby 3.3.10 / Gosu 1.4.6 / Linux SDL offscreen。
Gosuの入力確認22項目成功、通常描画30フレーム。自動プレイヤーはふつうで80回成功・仮眠7回・最高ゲージ250.97・終了時72.78。
この自動プレイヤーは正答を知っていて反応も速い。人間の初見クリアや最適難易度を保証する結果ではない。

次のプレイテストでは「1日90秒の長さ」「各ゲームの難しさ」「1日に必要な成功回数」を中心に意見を集め、`config/balance.rb` の数値を調整する。
途中保存はまだ付けていない。歩行アニメーションも仮素材としている。

## 10. 視聴者視点とアニメーション

- 初期表示は視聴者視点。Vでプレイヤー視点へ切替でき、ゲームの時計やゲージは共通。
- ミニゲームは左側の幅760pxに収め、右側288pxのチャットを常時表示する。描画の横方向の変換と同じ変換をクリック範囲にも適用する。
- PCウィンドウ風の枠、ラベンダー・ピンクの配色、配信チャットで『NEEDY GIRL OVERDOSE』を意識した雰囲気を作る。既存作品の素材・台詞・画面そのものは使っていない。
- コメントはゲーム内生成。ネットワーク通信、実際の視聴者数、実在のコメントの転載はない。
- 筋トレの命中、記憶の正誤、泡のゾーン内外、反応ゲームの結果、ゲージ閾値、日付・勝敗をイベントとして実況する。
- 同時に流すコメントは最大12、表示待ちは最大20、履歴は16件。4レーンを等速で流し、同じレーンで文字が重ならない間隔を取る。
- 競技開始時に前の競技の流れるコメントを消す。チャット履歴は保持する。Cで流れるコメントを隠せる。
- コメントと幻覚は配信映像の中だけに描画し、得点バー・回答ボタン・睡眠ゲージを覆わない。
- 一時停止すると、ミニゲーム、ゲージ、コメント、幻覚タイマーがすべて止まる。

人物のスプライトは4列×5行。上から筋トレ・お風呂・サプリメント・整体・カメラ救出。
待機ループだけでなく、操作成功でリフト・星のきらめき・飛び起きる・カメラを捕まえるコマへ切り替える。
カメラ救出のミスでは、服を着たキャラクターの前に「しばらくお待ちください」を表示する。
生成シートの境界はアトラス座標で補正し、元画像データは維持する。生成時の指示は `ASSET_PROMPTS.md` に記録。

## 11. クイヤの幻覚

| 睡眠ゲージ | 表示 |
|---|---|
| 0〜549 | 出現しない |
| 550〜749 | 半透明のクイヤ1体 |
| 750〜899 | 2体、クイヤに反応するコメント |
| 900〜999 | 3体、より濃く表示 |

9キーを押すと驚いて逃げ、4.5秒間姿を消す。再使用まで6秒。回復効果や得点はない。
成功や仮眠でゲージが下がると、出現数もすぐに減る。Hで1体・低い不透明度・小さな揺れに切り替える。
クイヤは「9が嫌いな架空の動物」というネット上のネタを参照し、本ゲーム用の見た目を作った。
幻覚そのものは本ゲームの創作で、実在人物の症状を表現したものではない。
